# Agile UX, design patterns, and reusable resources

Chapter 13 describes AgileUX as efforts to integrate interaction-design techniques and processes with agile development. Shared iteration and user involvement do not remove the need to coordinate research, work practices, and documentation.

A design pattern records a solution to a problem in a context. Its name supports communication, while its context and rationale help a team decide whether the solution transfers to its own setting.

| Resource | What it supplies |
| --- | --- |
| Design pattern | Reusable design experience and a vocabulary |
| Open-source component | Code available for reuse under its license |
| Design tool | Support for activities such as sketching, simulation, or analysis |

The chapter distinguishes reuse of design knowledge from reuse of implementation resources. Selecting a tool does not establish that a design fits its users. ^[inferred]
