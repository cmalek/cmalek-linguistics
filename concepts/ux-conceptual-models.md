# Conceptual models and interaction types

A conceptual model describes what people can do with a product and which concepts they need to understand it. Its objects, attributes, operations, metaphors, and mappings give the design a coherent structure. Chapter 3 separates assumptions that require investigation from claims that still need support.

## Interaction types

| Type | Organizing action |
| --- | --- |
| Instructing | Tell the system what to do |
| Conversing | Exchange a two-way dialogue |
| Manipulating | Act on represented objects |
| Exploring | Move through a physical or virtual environment |
| Responding | React to a system-initiated suggestion or request |

These describe interaction, while [[concepts/ux-interface-selection]] concerns the technology through which it happens. A voice interface can support several interaction types.

The designer's model reaches users through the system image: interface behavior, documentation, and help. A mismatch can leave users with an inaccurate mental model. [[concepts/ux-cognition]] explains the cognitive side of that gap.
