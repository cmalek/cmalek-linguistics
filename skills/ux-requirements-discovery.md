# Discovering and expressing requirements

A requirement states what an intended product should do or how it should perform. Chapter 11 makes requirements discovery iterative: research, design, construction, and evaluation can all reveal changes to the understanding of the problem.

A useful account includes target users and capabilities, existing tasks and goals, context, and constraints. Specify how fulfillment will be assessed rather than leaving an aspiration such as appeal or speed undefined.

| Artifact | Role |
| --- | --- |
| Requirement statement | Expected behavior or performance |
| Persona | A representation that helps communicate the intended user |
| Scenario | A story about a product's use |
| Use case | A stepwise account of interaction |
| User story | An outcome or goal from a user's perspective |

These artifacts complement prototypes and discussion; one brief statement cannot communicate every aspect of a product's purpose. Existing documentation and activity records can contribute evidence alongside interviews, observation, questionnaires, probes, and contextual inquiry.

Use [[skills/ux-data-gathering]] to investigate the problem and [[skills/ux-prototyping]] to expose assumptions through concrete alternatives. [[skills/ux-evaluation-planning]] connects requirements to evidence of fulfillment.
